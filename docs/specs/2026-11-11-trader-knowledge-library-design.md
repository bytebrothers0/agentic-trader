# Trader-Knowledge Library & Agent Reasoning Upgrade — Design

**Date:** 2026-11-11
**Status:** Approved-by-delegation (user asleep; morning review veto window)
**Method:** `deep-research` skill — Observe → Experiment → Implement
**Scope guard:** additive only. No watcher/execution/store changes. `strategies/alchemy_mnsr.md` and `STRATEGY_ACTIVE` stay untouched until the operator approves the new master playbook.

---

## 1. Problem

Asked "what is the current bias?", the chat agent calls one D1 chart, loads BOS,
and answers "bearish" — correct by accident, shallow by construction. It reasons
like a rule-follower, not a trader with experience: no HTF/MTF/LTF alignment, no
read of where liquidity actually rests, no time context, no articulation of what
would change its mind, no notion that experienced traders sometimes *bend* rules
to protect capital or lock profit.

## 2. Goal

Make the agent carry the **universal body of trader knowledge** (the things every
competent trader knows regardless of entry model) and **reason procedurally** like
an experienced discretionary trader — then *prove* it does, by interviewing it
against live charts and grading its answers against the research.

Explicitly NOT: a new entry model. Entry models (`entry_model_01_h4_fvg.md`, …)
are the operator's own work and can lean on this library later.

## 3. Deliverables

### 3.1 Knowledge library — `strategies/knowledge/*.md`

One dense file per core competence, mapped to what the agent's detectors can
actually see and serve (`set_view` families, `level_lookup`, states):

| File | Teaches | Maps to detector |
|---|---|---|
| `market-structure.md` | swings, HH/HL/LH/LL, BOS vs CHoCH, internal vs external structure, HTF→LTF alignment | `bos` |
| `liquidity.md` | equal highs/lows, buy/sell-side pools, sweeps vs breaks, stop hunts, where liquidity *should* be but isn't (draw on liquidity) | `liquidity`, `crt`, `ts` |
| `fvg-imbalances.md` | FVG/IFVG, mitigation,失衡 as inefficiency; when an FVG is a real target vs noise | `fvg`, `ifvg` |
| `order-blocks.md` | origin of displacement, OB/breaker, mitigation vs invalidation | `ob` |
| `premium-discount.md` | dealing range, equilibrium, premium/discount, OTE; why direction is decided in discount (longs) / premium (shorts) | `sr`, `ocl`, `apex` |
| `time-sessions.md` | London/NY/Asia character for gold, killzones, why time filters location | (time context in briefings) |
| `qm-idm.md` | Quasimodo as failed SBR/RBS; inducement and why it gets swept first | `qm`, `idm` |
| `trendlines.md` | slope quality, breaks vs retests, trendline liquidity | `trendline` |
| `risk-management.md` | risk per idea not per trade, invalidation-first thinking, partials, exposure discipline | (proposal validation) |
| `trader-psychology.md` | process over outcome, no-trade is a position, FOMO/revenge discipline, when rules bend (capital protection, profit lock) — never as license to overtrade | (persona) |

Each file: **≤ ~40 lines**, structure: definition (research-verified) → how to
read it on this system's charts (tags/states/`level_lookup`) → how it feeds bias
→ common misreads → when the rule bends. Density over prose — "C, not Python".

### 3.2 Master playbook — `strategies/trader_core.md` (generated, ≤50 core lines)

Prompt-engineering core: trader identity, the reasoning procedure (context →
structure → liquidity → location → time → thesis with invalidation), explicit
"rules bend, but only for X" doctrine, psychology guardrails. Generated by
`tools/build_trader_core.py` which concatenates the header + knowledge files;
source of truth stays the topic files. **Not activated** until the operator
reviews it; then `STRATEGY_ACTIVE=trader_core` (one config edit, theirs to make).

### 3.3 Research log — `docs/research/2026-11-11-trader-knowledge/`

`sources.md` (deep-research capture format: ID, claim, evidence, grade, access)
+ `findings.md` (claim matrix, confidence levels, disagreements).

### 3.4 Interview harness — `tools/agent_interview.py`

Scripted Q&A through the **running server's HTTP API** (single process, no store
contention): "what's the current bias and why?", "where is liquidity resting?",
"is that sweep real?", "what would change your mind?" → for each answer, fetch
the turn's render_id and render the same chart for my own inspection → grade
against a research-derived checklist → write `docs/research/.../agent_grades.md`.

## 4. Method (deep-research mapped)

- **Observe:** separate searches per sub-question (definitions from ICT-derived
  and institutional sources; critiques and known failure modes; session/time
  behavior for XAUUSD; trading psychology literature). Open pages, not snippets.
- **Experiment:** triangulate each concept across 2–3 independent sources; hunt
  disconfirming evidence ("ICT concepts don't work", base-rate studies); grade
  sources A–D; build on A/B; **validate every agent answer against the rendered
  chart**, never against the agent's own confidence.
- **Implement:** the files above + graded findings + a repeatable interview
  harness so tomorrow's work is a command, not an archaeology dig.

## 5. Lifecycle / risk assessment (honest)

- **Model ceiling:** the free local model (nemotron) may be too weak to reason
  like an experienced trader no matter the prompt. Mitigation: procedure-shaped
  prompting (explicit steps beat vibes), short dense knowledge, and honest
  grading — if it can't, the report says so and names the minimum model bar.
- **Context budget:** system prompt + 11-tool schema ≈ 3.8k tokens already; the
  knowledge layer adds ~1.5–2.5k. Fine for the local provider; would breach the
  hosted Groq 7k ITPM cap — noted in the master playbook header for the operator.
- **Knowledge bloat / bloated prompt:** the ≤50-line core + per-topic files are
  the guardrail; generator enforces a hard line budget and fails the build if
  exceeded.
- **Self-confirmation risk:** I render charts myself and check the agent's
  price/level claims against tool-served numbers, never against its own answers.
- **Concurrent access:** interviews go through the operator's running server
  (single AgentService process) — no dual-writer store risk.
- **Cold-start fairness:** the agent is interviewed on whatever the market gives
  tonight; findings note the sample size and that grades are provisional.

## 6. Success criteria (morning review)

1. Topic files exist, dense, research-cited in the research log (not in the
   files themselves — files stay lean).
2. Master core ≤50 lines, built by script, not activated.
3. `agent_grades.md` shows the agent's actual answers, my chart-based
   verification of each claim, and a grade per answer — including failures.
4. A named shortlist of what to fix next (prompt wording vs model ceiling).
